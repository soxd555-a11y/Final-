QA Playbook (02)

Test Design เทคนิคการทดสอบ

Black-box testing techniques — นิยาม ขั้นตอน คำนวณ และตัวอย่าง test case

ภาพรวมเทคนิค

8 เทคนิคหลักของ Black-box testing สำหรับ design test case โดยแต่ละเทคนิคมีโครงเดียวกัน: นิยาม → ขั้นตอนทำ → ตัวอย่างคำนวณทีละบรรทัด → ตาราง test case → ข้อควรระวัง

1. Equivalence Partitioning (EP)

แบ่ง input เป็น group ของ equivalent values

2. Boundary Value Analysis (BVA)

ทดสอบค่าขอบ (boundary) ใกล้ min/max

3. Decision Table

แปล rules เป็น conditions/actions

4. State Transition

ออกแบบ state diagram + transition

5. Use Case

main / alternative / exception flow

6. Pairwise

test ทุกชุด pairwise

7. Error Guessing

คาดการณ์ error จากผู้ใช้/โค้ด

8. Cause-Effect

แบ่ง cause → effect

1. Equivalence Partitioning (EP)

นิยาม

แบ่ง domain ของ input เป็นกลุ่ม equivalent (ซ้ำปฏิบัติได้กัน) แล้ว select ตัวแทนต่อ group

ขั้นตอนทำ

  1. ระบุค่าที่ถือว่า valid / invalid
  2. แบ่งเป็น partition ย่อย
  3. เลือกตัวแทน 1 ค่าต่อ partition
  4. เทสคนั้นกับทุก partition

ตัวอย่างคำนวณ — ฟอร์มสมัครสมาชิก (อายุ 18–60 ปี)

Domain: [18, 60] (valid), [−∞, 17.99] ∪ [60.01, ∞] (invalid) → 3 partitions

EP
Partitions:
  P1: valid        -> ตัวแทน: 18 (min)
  P2: invalid (low) -> ตัวแทน: 17 (min-1)
  P3: invalid (high)-> ตัวแทน: 61 (max+1)

ตาราง Test Case (สมมุทั้ง 3)

Test CaseInputExpected
TC-EP-01age = 18ผ่าน (valid)
TC-EP-02age = 17fail (invalid < min)
TC-EP-03age = 61fail (invalid > max)

สรุปท่องจำ (Key Points)

  • EP ลดจำนวน test case แต่ครอบคลุม valid/invalid
  • เลือกตัวแทน 1 ค่าต่อ partition (เช่น min/max หรือค่าที่อยู่กลาง)

2. Boundary Value Analysis (BVA)

นิยาม

ทดสอบค่าขอบใกล้ขีดจุดเปลี่ยนค่า (boundary) — 2-value หรือ 3-value style

ขั้นตอนทำ (3-value style)

  1. ระบุค่าใกล้ขอบ: min−1, min, min+1, max−1, max, max+1
  2. คำนวณ expected จากกฎของระบบ
  3. เทสแต่ละค่า

ตัวอย่างคำนวณ — อายุ 18–60 ปี (BVA ต้องการให้ได้ 17, 18, 19, 59, 60, 61)

คำนวณซ้ำ 2 วิธี: (1) ใช้ list ค่าขอบ hand-calc, (2) ใช้ generateBVA(min, max) จาก tools.js

tools.js
QA.generateBVA(18, 60);
// → values: [17, 18, 19, 59, 60, 61] (min-1, min, min+1, max-1, max, max+1)
ค่าทดสอบExpectedหมายเหตุ
17fail (invalid < 18)min−1
18passmin
19passmin+1
59passmax−1
60passmax
61fail (invalid > 60)max+1

สรุปท่องจำ (Key Points)

  • ใส่ค่า min−1 / max+1 เสมอ เพราะ bug มักอยู่ใกล้ขอบ
  • Robust BVA เพิ่มค่าที่ห่างขอบ เช่น min−2, max+2

3. Decision Table Testing

นิยาม

แปล business rules เป็นตาราง conditions (C) → actions (D)

ตัวอย่าง — ส่วนลด (discount) ตามประเภทสมาชิก + ยอดซื้อ

ConditionC1C2
Actionส่วนลด (Discount)ส่วนลด (Discount)
Rule 1C1=T ∧ C2=T15%
Rule 2C1=T ∧ C2=F5%
Rule 3C1=F ∧ C2=T10%
Rule 4C1=F ∧ C2=F0%
 ตัวอย่างตารางลดส่วน Discount แบบ Decision Table

จำนวน rules = 2^n (n = จำนวน conditions) → นี่คือ 2n

สรุปท่องจำ (Key Points)

  • Collapse rules ที่ action ต่างกันต้องมี condition เดียวกันให้รวมกัน
  • Rule count = 2^n — ถ้า n สูงอาจไม่มีประโยชน์ ควร collapse

4. State Transition Testing

นิยาม

ออกแบบ state diagram ของโมเดล แล้ว transition table (รวม invalid transition)

ตัวอย่าง — ล็อกอินผิด 3 ครั้งแล้วบัญชีถูกล็อก

FromEventToResult
LockedLogin successUnlockedเข้าสู่ระบบได้
UnlockedLogin fail ×3Lockedถูกล็อก
LockedLogin failLockedไม่เปลี่ยน state
LockedReset passwordLockedInvalid transition (invalid)

คำนวณ coverage ระดับ 0-switch

จำนวน valid transitions / จำนวน valid transitions + invalid transitions

สรุปท่องจำ (Key Points)

  • ควรทดสอบทุก state และทุก transition
  • invalid transition ควรมี test case แยกเพราะอาจไม่ถูก handle

5. Use Case Testing

นิยาม

แปล use case เป็น happy path / alternative flow / exception flow

ตัวอย่าง — การสมัครสมาชิก

Main flow: กรอกข้อมูล → submit → ระบบสร้างบัญชี

Alternative flow: อีเมลซ้ำ → แจ้งข้อมูลผู้ใช้เดิม

Exception flow: รหัสผ่านยาวเกิน 16 ตัว → บล็ก/แจ้ง error

สรุปท่องจำ (Key Points)

  • แยก happy / alternative / exception ชัดเจน
  • ทุก exception flow ควรมี expected behavior

6. Pairwise / Combinatorial Testing

นิยาม

test ทุก pairwise combination ของ factors เพื่อพัฒนาเคสที่อาจพลาด

ตัวอย่าง — Browser × OS × Language

BrowserOSLanguage
ChromeWindowsth
ChromeWindowsen
ChromemacOSth
FirefoxWindowsen
SafarimacOSth
SafarimacOSen

ลดจำนวนเคสได้โดยการ pairwise — เช่น กินเคสที่ "อาจไม่คุกคาม" แต่อาจมี interaction

สรุปท่องจำ (Key Points)

  • Pairwise กว่า exhaustive testing มากสำหรับ factor หลายตัว
  • ใช้สูตร reduction เช่น IPO (In-Parameter-Order) หากต้องการลดจำนวน

7. Error Guessing / Exploratory Testing

นิยาม

ผู้เชี่ยวชาญคาด error จากลำดับขั้นและพฤติกรรมของระบบ

Checklist ที่ควรลอง

  • ค่าว่าง / ช่องว่างใน input
  • ตัวอักษรพิเศษ / ยาวเกิน
  • SQL injection string พื้นฐาน (' OR '1'='1)
  • emoji / ตัวเลขติดลบ / unicode
  • boundary value ที่เพิ่งพูด

สรุปท่องจำ (Key Points)

  • Exploratory testing คือ simultaneous learning & testing
  • Error guessing เก็บจาก log / ปัญหาจริงก่อน

8. Cause-Effect Graph

นิยาม

แยก causes → effects เพื่อหา combination ของ conditions ที่ทำให้ effect ถึง

เชื่อมกับ Decision Table — ใช้ cause-effect graph หา conditions ที่ต้องมีตัวเลือกเพิ่ม

สรุปท่องจำ (Key Points)

  • Cause = condition ที่ controllable, Effect = condition/result
  • ใช้ graph เพื่อหา association ระหว่าง conditions

ตารางเลือกเทคนิคให้เหมาะกับโจทย์

ถ้าถังโจทย์เป็น …ให้ใช้เทคนิค

Rule/สถานการณ์หลายเงื่อนไขDecision Table
