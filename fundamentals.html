QA Playbook (01)

Fundamentals / พื้นฐานการทดสอบซอฟต์แวร์

QA vs QC vs Testing, Verification vs Validation, principles, levels, types, lifecycle, metrics

1. Testing vs QA vs QC และ V vs V

มิติTestingQAQC
บทบาทรู้ว่ามี bug / ไม่มี bugกลไก/กระบวนการพัฒนาซอฟต์ให้มีคุณภาพตรวจสอบคุณภาพตอน develop
เป้าหมายFind defectsQuality culture / processVerify conformance

Verification vs Validation

มิติVerificationValidation
คำว่าสิ่งที่สร้างถูกต้องตาม spec หรือไม่สร้างของที่ผู้ใช้ต้องการหรือไม่
ตัวอย่างReview/test ตาม requirementทดสอบในปีกอบอุ่น (UAT)

สรุปท่องจำ (Key Points)

  • QC = kiểm tra (check) ในวงกว้างกว่า; QA = ระบบการบริหารจัดการ quality
  • Verification = ได้ไหม (built right); Validation = ควรไหม (built right)

2. Error / Defect / Failure และ Defect Life Cycle

ความสัมพันธ์: Error → Defect → Failure

error-defect-failure.txt
Error (Error) = ชั่วคราว/ปัญหาใน process ที่ทำให้ test ไม่ทำงานได้
Defect (Defect/Bug) = ปัญหาที่พบใน product ที่สร้างจาก error
Failure (Failure) = การทำงานที่ผิดจากที่คาดไว้ใน runtime

Defect Life Cycle

New → Assigned → Open → Fixed → Retest → Verified → Closed (+ Reopened / Rejected / Deferred)

สรุปท่องจำ (Key Points)

  • หลายระบบอาจเรียกขั้นตอนต่างกัน แต่ concept เดียวกัน
  • Reopened = ทดสอบ retest แล้วยัง fail → ปิดไม่ได้

3. 7 Testing Principles ของ ISTQB

#Principleคำอธิบายสั้น
1Fit for purposeเทคนิคเหมาะกับ context
2Based on riskออกแบบจากความเสี่ยง
3Progressiveทบทวน/พัฒนาอย่างต่อเนื่อง
4Feedbackผลลัพธ์ไปป้อน process
5Insuranceทดสอบพร้อมกันหลายสำหรับความมั่นใจ
6Complacencyต้องเตือนเรื่องความภูมิใจเกินจริง
7Prioritizationจัดลำดับความสำคัญของ test

สรุปท่องจำ (Key Points)

  • 7 ข้อคือแก่นของ ISTQB syllabus
  • ทั้ง 7 ข้อควรอ่าน/ทดสอบในชุดวิชา

4. SDLC vs STLC และ V-Model

STLC steps: Requirement analysis → Test planning → Test case design → Environment setup → Test execution → Test closure

V-Model: ฝั่ง Development จับคู่กับฝั่ง Testing (เทคโนโลยีสำรอง)

สรุปท่องจำ (Key Points)

  • V-Model แสดงการตรวจสอบทั้งก่อน (dev) และหลัง (test)
  • STLC เชื่อมกับ SDLC แต่เป็นเฉพาะ testing phase

Test Types (ตารางสั้น)

Typeคำจำกัด
FunctionalFeature ทำงานตาม requirement
Performanceเวลาตอบสนอง/ใช้ทรัพยากร
Loadกับ load จำกัด
Stressกับภาระสูงสุด

สรุปท่องจำ (Key Points)

  • Smoke = กันระเบิด; Sanity = ตรวจสอบลึกหลัง smoke
  • Regression ≠ Retesting: regression = regression suite; Retesting = retest bug fix

6. Static vs Dynamic Testing, Black/White/Grey-box, Test Pyramid

Static: Review, Walkthrough, Inspection — Dynamic: execution

Black-box: ไม่ดู internal; White-box: ดู internal; Grey-box: ผสม

Test Pyramid: Unit สูง → Integration → E2E ต่ำ (เหตุผล: speed, cost)

สรุปท่องจำ (Key Points)

  • Test Pyramid คือหลักของ modern E2E strategy
  • White-box ใช้กับโค้ด/coverage; Black-box ใช้กับ requirement

7. Manual vs Automation, TDD vs BDD

Manual: เหมาะ exploratory, usability, งาน rare. Automation: regression, repeat.

TDD: Red → Green → Refactor. BDD: Given-When-Then + Gherkin (Feature/Scenario/When/Then)

สรุปท่องจำ (Key Points)

  • BDD ยังใช้ Gherkin + automation (Given-When-Then) ร่วมกันได้

8. Severity vs Priority และ Quality Attributes

Severity vs Priority: table + 4 cases (High-High, High-Low, Low-High, Low-Low)

ISO/IEC 25010: Functional Suitability, Performance Efficiency, Compatibility, Usability, Reliability, Security, Maintainability, Protection

สรุปท่องจำ (Key Points)

  • Severity = อันตรายต่อ user/business; Priority = ความสำคัญใน release

9. Metrics และ Entry/Exit Criteria

Defect density = defects / (LOC or size). DDP = (defects found before release / total defects) × 100. Pass rate = passed / total × 100

สรุปท่องจำ (Key Points)

  • ทดสอบทั้งระบบต้องมี exit criteria ที่ชัด
  • Suspension/resumption criteria: ระบุเงื่อนไขหยุด/ resume test
