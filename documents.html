QA Playbook (04)

เอกสารและ Template สำหรับ Testing

Copy-paste template ที่ใช้จริง: Test Case, Bug Report, Test Plan, Test Summary, RTM, Risk-based Testing

1. Test Case Template

ฟิลด์ที่ต้องมี: Test Case ID, Title, Module, Preconditions, Test Steps, Test Data, Expected Result, Actual Result, Status, Priority, Type (positive/negative), Remarks

แบบ Markdown

test-case-template.md
| Test Case ID | Title | Module | Preconditions | Test Steps | Test Data | Expected Result | Actual Result | Status | Priority | Type | Remarks |
|---|---|---|---|---|---|---|---|---|---|---|---|
| TC-001 | Login success | Auth | user created | 1. goto /login 2. fill 3. click | email/password | redirect dashboard | - | Pass | High | Positive | - |

แบบ HTML Table

test-case-template.html
<table class="test-case">
  <tr><th>Test Case ID</th>...</th></tr>
</table>

2. Bug / Defect Report Template

ฟิลด์: Bug ID, Title, Environment (OS/Browser/Version), Steps to Reproduce, Expected vs Actual, Severity, Priority, Status, Attachments, Reported by/date, Assigned to

ตัวอย่างที่เขียนดี vs เขียนแย่

มิติเขียนดีเขียนแย่
Steps"1. goto /login 2. fill email 3. fill pass 4. click Login → error shows""It doesn't work"
Expected"Redirect to /dashboard after valid login""Should be better"
Severity/PrioritySeverity: High, Priority: High (block release)"ugly"

ตัวอย่าง Bug Report (Markdown)

bug-report.md
# Bug Report: รูปสินค้าทั้งหมดเป็น broken image เมื่อ login ด้วย problem_user

**Bug ID:** BUG-001
**Environment:** Chrome 126 / Windows 11 / staging
**Steps to Reproduce:** goto /login → fill problem_user/problem → click Login
**Expected:** Product images render normally
**Actual:** All images broken (404)
**Severity:** High
**Priority:** High
**Status:** Open
**Attachments:** screenshot-001.png, network-log.txt

3. Test Plan (IEEE 829 แบบย่อ)

ฟิลด์: Objective, Scope (in/out), Test approach, Test items, Features to be tested, Entry/Exit criteria, Environment, Schedule, Resources/Roles, Risks & mitigation, Deliverables

สรุปท่องจำ (Key Points)

  • Entry criteria: build พร้อม, test data ครบ, env พร้อม
  • Exit criteria: coverage ถึง agreed level, no open critical bug

4. Test Summary Report

จำนวนเคส pass/fail/blocked, defect ตาม severity, coverage, ข้อสรุป/ข้อแนะนำ

ตัวอย่าง Test Summary (Markdown)

summary.md
# Test Summary Report — v1.2.0

- Total: 120, Passed: 112, Failed: 5, Blocked: 3
- Defect: Critical 1, Major 2, Minor 2
- Coverage: statement 85%, branch 70%
- ข้อสรุป: regression ใน checkout flow
- ข้อแนะนำ: เพิ่ม regression suite

6. Risk-based Testing

ตาราง Likelihood × Impact

LikelihoodImpactความสำคัญ
HighHighต้อง test ก่อน release (critical)
HighLowควรมี test
LowHighควรมี test (low cost)
LowLowไม่จำเป็นต้อง test
